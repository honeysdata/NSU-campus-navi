# 3주 프로젝트 체크리스트

목표: 남서울대학교 일부 영역에서 OSM 기반 보행 라벨을 만들고, Overlay 검수와 Buffer 폭 개선을 거쳐 학습 가능한 데이터셋과 모델을 완성한다.

## 전체 완료 기준

- [ ] 동일한 항공영상 타일과 라벨 Mask가 1:1로 연결된다.
- [ ] 라벨 Overlay를 사람이 확인하고 수정할 수 있다.
- [ ] 고정 폭 라벨과 개선 Buffer 라벨의 차이를 비교할 수 있다.
- [ ] 검수 라벨로 재생성한 데이터셋으로 모델을 재학습한다.
- [ ] 학습 전후 예측 이미지와 Dice·IoU·loss를 기록한다.
- [ ] 데이터셋 버전과 모델 체크포인트를 구분해 저장한다.

---

## 1주차 — 고정 폭 Mask 파일럿

### 목표

남서울대학교 일부 영역을 대상으로 항공영상, OSM 보행로, 고정 폭 Mask를 연결해 첫 번째 학습 데이터셋을 만든다.

### 작업 체크리스트

#### 환경과 범위

- [ ] 작업 디렉토리 확인

  ```bash
  cd /Users/song/PROJECT/gis
  ```

- [ ] Python·uv 환경 확인

  ```bash
  uv sync --extra ml --extra server
  ```

- [ ] 파일럿 영역과 줌 레벨을 문서화한다.
- [ ] 파일럿에 사용할 타일 수를 정한다.
- [ ] 타일 ID 규칙을 확인한다: `zoom_x_y`.

#### 원본 데이터 수집

- [ ] OSM 원본을 `data/raw/nsu_map.osm`에 준비한다.
- [ ] 항공영상 JPG 타일을 확보한다.
- [ ] 항공영상과 OSM의 좌표 범위를 확인한다.
- [ ] 원본 데이터의 출처와 사용 조건을 기록한다.

#### 고정 폭 Mask 생성

- [ ] OSM의 `footway`, `path`, `pedestrian`, `steps` 등 보행로를 선별한다.
- [ ] OSM LineString을 현재 파일럿의 고정 폭 규칙으로 rasterize한다.
- [ ] 항공영상과 같은 `tile_id`의 Mask를 생성한다.
- [ ] Mask의 크기와 좌표 방향이 항공영상과 일치하는지 확인한다.
- [ ] 생성 명령을 기록한다.

  ```bash
  uv run python scripts/build_nsu_dataset.py
  ```

#### 1차 품질 확인

- [ ] 빈 Mask 타일이 없는지 확인한다.
- [ ] 항공영상은 있는데 Mask가 없는 타일이 없는지 확인한다.
- [ ] Mask가 건물·도로·수면 등 비보행 영역을 과도하게 포함하지 않는지 확인한다.
- [ ] 보행로가 1px 선으로만 남지 않고 일정 폭을 갖는지 확인한다.
- [ ] 샘플 3~5개를 골라 이미지와 Mask를 나란히 확인한다.

### 1주차 산출물

- [ ] `data/datasets/namseoul_university/images/`
- [ ] `data/datasets/namseoul_university/masks/`
- [ ] `data/datasets/namseoul_university/metadata.json`
- [ ] `data/datasets/namseoul_university/label_overlay.png`
- [ ] 파일럿 범위·타일 목록·고정 폭 규칙 문서

### 1주차 완료 조건

> 항공영상 1장과 동일 위치의 Mask 1장을 열었을 때 서로 정확히 겹치고, 학습 데이터로 사용할 수 있는 수준이다.

## 2주차 — Overlay 확인 및 사람 라벨 검수

### 목표

OSM 기반 pseudo-label을 항공영상과 Overlay해 사람이 검수하고, 수정 가능한 검수본을 만든다.

### 작업 체크리스트

#### Overlay 확인

- [ ] 항공영상 위에 Mask를 투명도 적용해 표시한다.
- [ ] 보행로 중심선과 실제 보행 가능 영역의 차이를 확인한다.
- [ ] 폭이 너무 좁거나 넓은 구간을 표시한다.
- [ ] 누락된 보행로를 표시한다.
- [ ] 보행로가 아닌 영역에 포함된 라벨을 표시한다.
- [ ] 광장·계단·연결 통로처럼 단순 선 라벨로 표현하기 어려운 영역을 별도로 기록한다.

#### 사람 검수

- [ ] 검수 기준을 통일한다.
  - 추가: 실제 보행 가능하지만 라벨에 없는 영역
  - 삭제: 실제 보행 불가능하지만 라벨에 포함된 영역
  - 수정: 위치·폭·연결성이 부정확한 영역
  - 보류: 항공영상만으로 판단하기 어려운 영역
- [ ] 검수자별 수정 기준을 공유한다.
- [ ] 수정된 선의 `review_status`를 기록한다.
- [ ] 검수본을 원본과 분리해 저장한다.
- [ ] 검수 완료 후 GeoJSON을 다운로드한다.

#### 검수 데이터 품질 확인

- [ ] 추가된 선이 기존 그래프와 연결되는지 확인한다.
- [ ] 삭제된 선이 유일한 연결 통로인지 확인한다.
- [ ] 교차점과 끝점이 끊기지 않았는지 확인한다.
- [ ] 자기 교차·중복 선·비정상적으로 긴 선을 확인한다.
- [ ] 검수본의 좌표계가 원본과 같은지 확인한다.

### 2주차 산출물

- [ ] Overlay 검수 이미지
- [ ] `labels_reviewed.geojson`
- [ ] 추가·삭제·수정된 라벨 목록
- [ ] 검수 기준 문서
- [ ] 검수 전후 변경 통계

### 2주차 완료 조건

> 사람이 Overlay를 보고 보행 가능 영역의 추가·삭제·폭 수정 여부를 판단할 수 있고, 수정 결과가 GeoJSON으로 보존된다.

## 3주차 — Buffer 폭 개선·라벨 재생성·모델 재학습

### 목표

사람 검수 결과와 실제 보행로 폭을 반영해 Mask를 다시 만들고, 개선된 라벨로 모델을 재학습한다.

### 작업 체크리스트

#### Buffer 폭 기준 수립

- [ ] 대상 보행로를 폭 유형으로 분류한다.
  - 일반 보행로
  - 넓은 보행로
  - 계단·경사로
  - 광장·보행 공간
- [ ] 고정 픽셀 폭과 실제 미터 폭의 차이를 기록한다.
- [ ] 줌 레벨별 pixel-to-meter 변환 기준을 정한다.
- [ ] 폭 파라미터를 설정 파일 또는 CLI 옵션으로 분리한다.
- [ ] 구간별 Buffer 폭 적용 가능 여부를 검토한다.

#### 개선 Mask 생성

- [ ] 검수 GeoJSON을 입력으로 사용한다.
- [ ] GIS 좌표계에서 Buffer를 적용한다.
- [ ] Buffer Polygon을 항공영상 타일에 rasterize한다.
- [ ] 개선 전 고정 폭 Mask와 개선 후 Mask를 비교한다.
- [ ] Overlay로 폭·누락·연결성을 재확인한다.
- [ ] 개선 데이터셋 버전을 별도 디렉토리 또는 메타데이터로 기록한다.

#### 모델 재학습

- [ ] 동일한 train/validation 분할 기준을 유지한다.
- [ ] 기본 U-Net을 개선 라벨로 재학습한다.
- [ ] U-Net + MobileNetV3를 개선 라벨로 재학습한다.
- [ ] 동일한 epoch·threshold·loss 설정으로 비교한다.
- [ ] 체크포인트 파일명에 데이터셋 버전과 모델명을 포함한다.
- [ ] 학습 시간과 epoch별 loss를 저장한다.

  ```bash
  uv run python scripts/train_unet.py
  uv run python scripts/train_mobilenet_full.py
  uv run python scripts/compare_models.py
  ```

#### 결과 비교

- [ ] 개선 전후의 예측 Overlay를 같은 샘플로 비교한다.
- [ ] Dice를 비교한다.
- [ ] IoU를 비교한다.
- [ ] 길이 끊김·과대 확장·광장 오인식 여부를 확인한다.
- [ ] 학습 데이터에만 잘 맞는지 별도 타일에서도 확인한다.
- [ ] 모델 선택 근거를 기록한다.

#### 다음 단계 판단

- [ ] 예측 Mask가 연결된 보행 영역을 안정적으로 표현하는지 확인한다.
- [ ] 연결성이 충분하면 Mask→Graph 변환 단계로 진행한다.
- [ ] 길이 끊김이 많으면 Buffer·검수 라벨을 먼저 개선한다.
- [ ] 두 모델 결과와 한계점을 문서화한다.
